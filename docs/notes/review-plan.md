# Critical Code Review Plan

## Scope

All Go source files (non-test) in the dockertest v4 library. ~24 files, ~6,800
lines.

## Review Areas

### 1. API Design & Public Surface

- Are the exported types, functions, and methods well-designed?
- Is the functional options pattern used consistently and correctly?
- Are there any unnecessary exports?
- Is the API intuitive for end users?

### 2. Error Handling

- Are errors wrapped with sufficient context?
- Is `errors.Is()`/`errors.As()` used correctly (never `==`)?
- Are sentinel errors appropriate and well-defined?
- Are errors silently swallowed anywhere?

### 3. Resource Management & Leaks

- Are Docker resources (containers, networks, images) always cleaned up?
- Are HTTP response bodies closed?
- Are goroutines properly managed?
- Is `io.ReadAll` used on potentially large streams without limits?

### 4. Concurrency Safety

- Is the registry truly thread-safe?
- Are there race conditions in Pool operations?
- Is the cleanup logic safe under concurrent use?

### 5. Context Propagation

- Is `context.Context` always passed from caller (never `context.Background()`)?
- Are contexts used for cancellation where appropriate?

### 6. Code Simplicity & Dead Code

- Are there unnecessary abstractions or helpers?
- Is there dead code or unused parameters?
- Can anything be simplified using stdlib?

### 7. Correctness

- Is retry logic correct (backoff, timeout behavior)?
- Is port mapping logic correct for all edge cases?
- Is container reuse logic correct?
- Are there any subtle bugs in the build pipeline?

### 8. Test Quality (read-only review, no modifications)

- Are tests comprehensive?
- Are there missing edge cases?
- Are tests deterministic?

## Execution

Dispatch parallel review agents, one per major source file group:

- Group A: pool.go, options.go, errors.go (core orchestration)
- Group B: resource.go, retry.go (resource & retry)
- Group C: network.go (networking)
- Group D: build.go (image building)
- Group E: registry.go (container reuse)
- Group F: internal/client/ (docker client abstraction)
- Group G: Test files (quality review)
